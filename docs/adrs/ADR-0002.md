# ADR-0002: Money as Integer Cents

| Field | Value |
|---|---|
| **Status** | Accepted |
| **Date** | October 2026 |

## Context
Floating-point arithmetic (IEEE 754, e.g., `float32`, `float64`) cannot represent many base-10 decimal fractions accurately. In financial software, binary floating-point representation causes silent rounding errors that violate ledger invariants and result in balance divergence.

## Decision
Store and transmit all monetary amounts as 64-bit signed integers (`int64` in Go, `BIGINT` in PostgreSQL), representing the smallest fractional currency unit (cents). Currency formatting and decimal rendering occur strictly at presentation boundaries. A single currency (e.g., BRL / USD) is assumed in v1.

## Consequences
- **Positive:** Exact arithmetic with zero rounding errors across all operations.
- **Positive:** Fast, native integer CPU operations without allocation overhead.
- **Trade-off:** Multi-currency support in future versions will require explicitly storing the currency code and handling distinct precision rules.

## Alternatives Considered
- **Arbitrary precision decimal types (e.g., `shopspring/decimal`, PostgreSQL `NUMERIC`):** Exact, but heavier in memory, slower in arithmetic computation, and incurs heap allocations.
- **Floating-point (`float64`):** Strictly rejected due to financial inaccuracy.
